# 🌸 نظام روضة ماما ماريا لإدارة الدروس والأنشطة

تطبيق ويب كامل (خلفية + واجهة) لإدارة تدفق الدروس والأنشطة التربوية بين
**المديرة التربوية** و**المربيات**، مع رؤية شاملة لـ**مديرة الروضة** ومتابعة
مباشرة لـ**أولياء الأمور**.

## المزايا

- **تسجيل دخول بالأدوار**: مديرة الروضة (إدارة عامة)، المديرة التربوية، المربية، ولي الأمر.
- **تقويم أسبوعي وشهري** لعرض الدروس والأنشطة بحسب الفصل والتاريخ.
- **إنشاء دروس/أنشطة** من المديرة التربوية مع وصف، هدف تربوي، مواد مطلوبة، وأولوية، وإرسالها لفصل واحد أو أكثر دفعة واحدة.
- **إرفاق ملفات وصور** بالدرس/النشاط (حتى 8 ملفات، 15 ميجابايت لكل ملف).
- **تأكيد الاستلام والتنفيذ** من المربية، مع إمكانية إضافة ملاحظات وصور فعلية من التنفيذ.
- **إشعارات فورية** (داخل النظام): عند إرسال درس جديد، عند تأكيد الاستلام، وعند تأكيد التنفيذ — تصل تلقائيًا للأطراف المعنية (المربية، المديرة التربوية، مديرة الروضة، وولي الأمر عند التنفيذ).
- **لوحة تحكم إدارية** بإحصائيات أسبوعية (عدد المهام، نسب الإنجاز لكل فصل، عدد المربيات/الفصول/الأطفال).
- **إدارة المستخدمين والفصول والأطفال** من مديرة الروضة.
- **متابعة أولياء الأمور**: صفحة مخصصة تعرض كل نشاط تم تنفيذه فعليًا لفصل طفلهم مع الصور والملاحظات.
- تصميم عربي (RTL) احترافي، متجاوب مع الجوال والتابلت والحاسوب.

## التقنيات المستخدمة

- Node.js + Express 5
- قاعدة بيانات SQLite (عبر better-sqlite3) — ملف واحد، لا حاجة لخادم قاعدة بيانات منفصل
- محرك القوالب EJS
- الجلسات (Sessions) مع تشفير كلمات المرور عبر bcrypt
- رفع الملفات عبر Multer

## التشغيل محليًا

**المتطلبات:** Node.js إصدار 18 أو أحدث.

```bash
# 1) تثبيت الحزم
npm install

# 2) تشغيل الخادم
npm start
```

عند أول تشغيل فقط، يقوم التطبيق تلقائيًا بتعبئة قاعدة البيانات ببيانات
أولية (حسابات تجريبية + فصلين). لا حاجة لأي خطوة يدوية إضافية. (يمكن أيضًا
تشغيل هذه التعبئة يدويًا في أي وقت عبر `npm run seed` — لن تكرر البيانات إذا
كانت موجودة أصلًا.)

بعدها افتح المتصفح على: `http://localhost:3000`

> يمكن تغيير المنفذ عبر متغير البيئة `PORT` (مثال: `PORT=8080 npm start`).

### حسابات تجريبية (تُنشأ تلقائيًا عند أول تشغيل)

| الدور | البريد الإلكتروني | كلمة المرور |
|---|---|---|
| مديرة الروضة (إدارة عامة) | mama.mariakids@gmail.com | Admin@2026 |
| المديرة التربوية | director@mamamaria.test | Director@123 |
| مربية - فصل البراعم | teacher1@mamamaria.test | Teacher@123 |
| مربية - فصل الفراشات | teacher2@mamamaria.test | Teacher@123 |

يمكنه تغيير كلمة مروره بنفسه من أيقونة المفتاح 🔑 المجاورة لاسمه أعلى الصفحة
(`/account/change-password`). كذلك يمكن لمديرة الروضة من صفحة "المستخدمون"
إضافة حسابات حقيقية جديدة، وحذف أو إيقاف الحسابات التجريبية بعد ذلك.

## النشر (Deployment)

### الطريقة الموصى بها: Render (مع دليل خطوة بخطوة منفصل)

هذا المشروع يتضمن ملف `render.yaml` جاهزًا (Render Blueprint)، بحيث عند ربط
المستودع بحساب Render يقوم Render تلقائيًا بإنشاء الخدمة **مع قرص دائم
(Persistent Disk)** لحفظ قاعدة البيانات والصور بشكل دائم — لا حاجة لأي إعداد
يدوي إضافي. هذا يتطلب خطة مدفوعة صغيرة (خطة Starter، حوالي 7 دولار/شهر +
أقل من دولار للقرص) لأن الخطط المجانية في كل منصات الاستضافة الحالية تمسح
البيانات دوريًا، وهو غير مناسب لبيانات حقيقية عن الأطفال والدروس.

**يوجد دليل مصور خطوة بخطوة كامل غير تقني منفصل** يشرح كل شيء من الصفر
(إنشاء حساب GitHub، رفع الملفات، ربط Render، والحصول على الرابط النهائي) —
اطلبيه إذا لم يصلك.

### بدائل أخرى

1. **VPS عادي** (مثل DigitalOcean / Hetzner / خادم استضافة يدعم Node.js):
   - ارفعي المشروع، نفذي `npm install --production`، ثم شغّليه بواسطة
     [pm2](https://pm2.keymetrics.io) أو كخدمة systemd حتى يبقى يعمل باستمرار:
     ```bash
     npm install -g pm2
     pm2 start app.js --name mamamaria
     pm2 save
     ```
   - ضعي خادم Nginx أمامه كـ reverse proxy مع شهادة SSL مجانية (Let's Encrypt / Certbot).

2. **منصات استضافة أخرى** (Railway، Fly.io وغيرها): نفس المبدأ — اربطي
   المستودع، أمر البدء `npm start`، وتأكدي من ربط تخزين دائم (Volume/Disk)
   وضبط متغير `DATA_DIR` ليشير إلى مساره (انظري الجدول أدناه)، وإلا ستُفقد
   البيانات عند كل إعادة نشر أو إعادة تشغيل.

### متغيرات البيئة المهمة

| المتغير | الوصف | القيمة الافتراضية |
|---|---|---|
| `PORT` | منفذ تشغيل الخادم | 3000 |
| `SESSION_SECRET` | مفتاح تشفير الجلسات — **غيّريه في الإنتاج** إلى نص عشوائي طويل (Render Blueprint يولّده تلقائيًا) | قيمة افتراضية غير آمنة |
| `NODE_ENV` | اضبطيه على `production` عند النشر خلف HTTPS لتفعيل الكوكيز الآمنة | (غير مضبوط) |
| `DATA_DIR` | مسار مجلد دائم لحفظ قاعدة البيانات وملفات الرفع (استخدميه فقط عند النشر على استضافة بها قرص دائم منفصل) | `db/` و`public/uploads/` محليًا |

مثال تشغيل في الإنتاج:
```bash
NODE_ENV=production SESSION_SECRET="ضعي هنا نصًا عشوائيًا طويلًا وسريًا" PORT=3000 npm start
```

## النسخ الاحتياطي

قاعدة البيانات بأكملها هي ملف واحد: `mamamaria.db` (داخل `db/` محليًا، أو
داخل مجلد `DATA_DIR` عند النشر على استضافة). لعمل نسخة احتياطية، يكفي نسخ
هذا الملف (ويفضّل إيقاف الخادم لحظة النسخ، أو استخدام أداة نسخ SQLite
الآمنة). كذلك يُنصح بعمل نسخة دورية من مجلد `uploads/` لأنه يحتوي كل الصور
والملفات المرفقة.

## أفكار لتطوير مستقبلي

- إشعارات عبر البريد الإلكتروني أو واتساب بالإضافة للإشعارات داخل النظام.
- تقارير شهرية قابلة للطباعة (PDF) لكل فصل.
- دردشة مباشرة بين المربية وولي الأمر.
- دعم عدة روضات (multi-tenant) إن أردتِ توسيع النظام لفروع أخرى.
